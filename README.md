### Knowledge Elevate & Adaptation

> **Two adaptive-learning experiences. One vision.**

# 🧠 What is KEA × AURA?

Traditional education often gives every student the same content, the same difficulty, and the same pace.

But students don't learn in the same way.

One student may understand a concept immediately, while another may need a simpler explanation, a prerequisite refresher, more practice, or a real-world example.

KEA × AURA is designed around this idea:

> **Every student should be able to reach the same learning outcome, but they shouldn't have to take the same path to get there.**

The platform continuously considers a student's understanding, performance, interests, mistakes, and learning behavior to make the experience more relevant to them.

# 🎯 The Problem We Are Solving

Students often struggle silently.

A student might:

- Have a weak prerequisite
- Repeatedly make the same mistake
- Understand theory but struggle with application
- Need more practice
- Need a different explanation
- Lose interest because examples don't relate to them
- Spend too much time on a concept
- Continue to the next topic without actually mastering the previous one

Traditional learning platforms may record the marks, but they don't always understand **why the student is struggling**.

KEA × AURA focuses on identifying these problems while the student is learning.

---

# 💡 Our Approach

Instead of asking:

> "Did the student get the answer right?"

KEA × AURA tries to understand:

> "Does the student actually understand the concept, and what should they do next?"

The platform can adapt based on:

- Accuracy

- Concept mastery
- Prerequisite mastery
- Learning pace
- Repeated mistakes
- Time spent
- Hint dependency
- Interests
- Engagement
- Confidence

This allows the experience to become more personalized as the student continues learning.

# 🔐 Prerequisite-Based Learning

KEA × AURA does not treat a subject as simply a list of chapters.

Concepts depend on other concepts.

For example:

```text
Electric Current
       ↓
Voltage
       ↓
Resistance
       ↓
Ohm's Law
```

If a student hasn't understood Resistance sufficiently, the system can identify that prerequisite gap before the student moves further.

Instead of simply saying:

> "You got the answer wrong."

The system can say:

> **"You may need to strengthen Resistance before continuing with Ohm's Law."**

This gives the student a clear next step.

---

# 📈 Mastery-Based Progress

KEA × AURA focuses on mastery rather than simply completing chapters.

A student's progress can take into account:

- Quiz performance
- Recent performance
- Prerequisite understanding
- Retention
- Practical or lab performance

This helps determine whether a student is:

```text
Not Ready
    ↓
Learning
    ↓
Proficient
    ↓
Mastered
```

The goal is to make sure that moving forward actually represents learning.

---

# 🎚️ Adaptive Difficulty

Questions can adapt according to how the student is performing.

For example:

```text
Strong performance
       ↓
Increase difficulty

Average performance
       ↓
Maintain difficulty

Repeated mistakes
       ↓
Reduce difficulty
       +
Check prerequisites
```

This prevents students from being stuck with content that is either too easy or too difficult.

# 🌍 Learning Through Real-World Context

One of the important parts of KEA × AURA is connecting academic concepts with the real world.

We use **SerpApi** to retrieve relevant information from search engines.

For example, if a student is learning **Ohm's Law** and has selected **Space** as an interest, the platform can retrieve information related to:

- Spacecraft electrical systems
- Satellite power systems
- Space technology
- Electrical applications in missions

The purpose isn't to replace academic content.

It is to help answer:

> **"Where does what I'm learning actually matter?"**

This makes learning more relatable and helps students connect classroom concepts with the world around them.

---

# 🔒 AI Guardrails

When AI re-themes or adapts educational content, the core academic structure must remain unchanged.

The system protects:

- Numerical values
- Variables
- Formulas
- Expected answers
- Learning objectives
- Difficulty
- Required reasoning

For example:

### Original

> A circuit has a 12V source and a resistance of 6Ω. Calculate the current.

### Personalized

> Imagine a spacecraft instrument powered by a 12V supply with a resistance of 6Ω. Calculate the current.

The story and context change.

The academic problem does not.

If generated content fails validation, the original content can be used instead.

---

# 🚨 Real-Time Struggle Detection

KEA × AURA is designed to identify learning difficulties before they become major problems.

It can look at signals such as:

- Repeated incorrect answers
- Low accuracy
- Excessive time
- Repeated hints
- Skipped questions
- Weak prerequisites
- Repeated attempts

When these signals indicate that a student may be struggling, the system can recommend intervention.

For example:

> **Aarav — High Intervention Risk**
>
> Topic: Ohm's Law  
> Main issue: Resistance prerequisite  
> Recommended action: Practice Resistance + virtual lab

# 👩‍🏫 Human-in-the-Loop Intervention

We don't believe AI should replace teachers.

AI helps identify patterns and recommend actions.

The teacher remains responsible for deciding what intervention is appropriate.

A facilitator can:

- View students who need attention
- Understand why a student is struggling
- Assign remedial activities
- Recommend a virtual lab
- Encourage the student
- Start an intervention
- Track progress
- Mark an intervention as resolved

The idea is:

> **AI detects. AI explains. AI recommends. Humans decide.**

# 🔄 How the Experience Works

The student's learning experience continuously adapts.

A student starts learning a concept.

The platform observes their performance.

If they understand it, the experience can become more challenging.

If they struggle, the platform looks for the likely reason.

If the problem is a prerequisite, the student can be guided back to that concept.

If the student continues struggling, a facilitator can be brought into the process.

Once the student improves, the system can reassess their mastery and allow them to progress.

The goal is not simply to complete a lesson.

The goal is to **actually understand it**.

# 🎬 Hackathon Demo Story

Our primary demonstration follows a student named **Aarav**.

Aarav wants to learn **Ohm's Law**.

He begins his personalized learning journey.

KEA identifies that his understanding of **Resistance** is not strong enough.

Instead of simply letting him continue, the platform guides him toward the prerequisite.

Aarav practices the concept.

Because he is interested in **Space**, the learning experience can connect examples to spacecraft and space technology.

He then takes part in an interactive learning activity.

As he continues, the platform notices repeated mistakes.

His struggle level increases.

KEA × AURA recommends an intervention.

The facilitator sees Aarav's situation and receives a recommended action.

The facilitator assigns a prerequisite refresher.

Aarav improves.

His mastery increases.

The next concept becomes available.

This demonstrates the central philosophy of KEA × AURA:

> **Understand the student → Adapt the learning → Detect struggle → Involve the teacher → Improve mastery.**

# 💻 Getting Started

## 1. Clone the repository

```bash
git clone <repository-url>
cd <project-folder>
```

## 2. Install dependencies

```bash
npm install
```

## 3. Configure environment variables

Create a `.env.local` file and add the required credentials:

```env
SUPABASE_URL=your_supabase_url
SUPABASE_ANON_KEY=your_supabase_anon_key
GROQ_API_KEY=your_groq_api_key
SERPAPI_KEY=your_serpapi_key
OPENROUTER_API_KEY=your_openrouter_api_key
```

Add the required NVIDIA NIM configuration if it is enabled in the current deployment.

## 4. Start the development server

```bash
npm run dev
```

Open:

```text
http://localhost:3000
```
